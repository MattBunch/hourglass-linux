# Linux Feature Parity

| Feature | Windows Status | Linux Scaffold Status | Linux Plan |
|---|---|---|---|
| Timer parsing | Implemented in legacy app | Extracted to `Hourglass.Core` with tests | Keep behavior stable while integrating the Linux UI. |
| Timer state | Implemented in legacy app | Core serialization DTOs and timer-start model extracted | Continue extracting platform-neutral timer/session state before settings migration. |
| Countdown timing | Uses WPF `DispatcherTimer` and `DateTime.Now` | Monotonic `CountdownEngine` implemented in `Hourglass.Core` | Use Avalonia timers only for UI refresh ticks. |
| Timer UI | WPF | Avalonia timer UI backed by `Hourglass.Core`, including restart, full-screen mode, persistent completion emphasis, replayable invalid-input feedback, reverse progress, elapsed-time display, looping timers, close-on-expiry, lock-interface behavior, multiple independent timer windows, window-title modes, and active-session window geometry restore | Continue adding parity features without moving window or animation effects into Core. |
| Notifications | Windows notification area balloon behavior | `INotificationService` with Linux `notify-send` backend | Keep notification delivery best-effort; app UI remains recoverable state. |
| Taskbar/dock progress | Windows taskbar progress states | `IDesktopProgressService` boundary with persisted **Show progress in taskbar** option, conservative desktop detection, Unity LauncherEntry backend for documented compatible docks, and unsupported Linux no-op backend | Validate exact desktop/dock combinations before claiming visible support; add separate backends for non-Unity-compatible environments later. |
| Tray/status icon | WinForms `NotifyIcon` | Optional `IStatusIconService` boundary with an Avalonia status icon backend for recognized tray-capable desktops and an unsupported no-op backend elsewhere | Disabled by default; desktop support must be validated per exact desktop/panel combination. |
| Keep awake | Windows execution state APIs | `ISessionInhibitor` with Linux `systemd-inhibit` backend plus a persistent **Do not keep computer awake** preference | Add portal backend later if packaging requires it. |
| Wake from suspend | Windows waitable timer resume behavior | Disabled-by-default `IWakeAlarmService` boundary with a conservative RTC wakealarm backend | Keep hidden from normal UI until physical-hardware, permission, and packaging reliability are proven. |
| Audio alerts | Windows-focused implementation | `IAudioAlertService` with best-effort Linux process backend, built-in Loud/Normal/Quiet beep selection, `None`, preview/stop-preview commands, per-sound availability checks, and stoppable looping playback handles | User-selected audio files remain deferred until sandbox and file-permission behavior is designed. |
| Settings | .NET Framework settings | Linux JSON settings store for recent inputs, saved timer definitions, active-session restoration, notifications, sound, theme preferences, custom themes, active-session window geometry, always-on-top, pop-up-on-expiry, prompt-on-exit, and expanded timer options | Keep schemas versioned and backward-compatible as advanced parity features are added. |
| Single instance | Windows Forms application base with command-line handoff | `ISingleInstanceService` with Linux advisory file lock plus Unix socket handoff for activation and timer-start requests | Keep the supported Linux command-line surface documented and test socket behavior under packaged namespaces. |
| Updates | Windows in-app update check | Linux update policy documented with no in-app updater, no updater UUID, and no silent downloads | Package channels own updates; future network checks must be opt-in and documented. |
| Packaging | MSI, bundle, portable Windows build | Reproducible `linux-x64` publish script, AppDir script, package validator, Flatpak/AppImage metadata, and CI artifacts | Flatpak first, AppImage second; signing and repository submission remain future work. |

The Linux MVP should not promise complete feature parity. It should prioritize a reliable native timer experience with notifications, sound, settings, and testable timing behavior.

Optional desktop integrations use narrow platform-service boundaries. Unsupported fallbacks are explicit no-op services that report unavailable capabilities and keep normal timer workflows running. For capability-bearing services, `IsSupported` means a backend was selected and initialized; it does not guarantee that a particular desktop, dock, notification daemon, or panel visibly rendered the requested effect.

Optional integration failures are classified as best-effort, user-requested, startup/configuration, or data-recovery events. Hourglass records structured diagnostics through an injectable sink, uses Trace diagnostics by default, suppresses repeated identical failures in memory, and keeps timer state changes independent from notification, audio, progress, status-icon, attention, wake, and settings-recovery failures.

Release candidates should use the [release validation checklist](release-validation-checklist.md) to record exact package, desktop, session, hardware, tester, date, result, notes, and skip-reason evidence before claiming native/AppImage, Flatpak, multi-monitor, wake-from-suspend, taskbar/dock progress, or status-icon support.

The right-click menu includes **About Hourglass** near the exit command. It opens an owned shell dialog with executable version/build/runtime details, GitHub and developer links, original-project attribution, MIT license information, and copyable diagnostic metadata. This dialog is application-shell behavior and does not pause, save, or mutate timer state.

The **Pop up when expired** context-menu option is enabled by default and persists across restarts. On expiry, Hourglass shows a short visual flash, retains a completion border until the timer is dismissed, and makes one best-effort request to show, restore, and activate the window. If the first restore request is refused, the Avalonia shell performs one hide/show remap before activating; it does not loop or alter the persisted always-on-top setting. Wayland compositors may still reject application-initiated activation or focus changes; notification, sound, and visual completion behavior continue independently when that happens.

Invalid timer submissions preserve the entered expression, keep the editor active, and replay a brief validation treatment on every attempt. Avalonia 12 does not currently expose a dependable cross-desktop reduced-motion preference, so these effects are deliberately short, conservative, and non-repeating, with durable static error and completion states.

Duration timers can be restarted from their original full duration using the timer controls, context menu, or `Ctrl+R`. Restart is unavailable for absolute-time expressions because repeating a past wall-clock target is ambiguous. Restarting uses the same countdown transition and session-inhibition boundaries as the other timer commands.

Keyboard command parity includes Space outside editable text and `Ctrl+P` for pause/resume, `Ctrl+S` for stop, `Ctrl+R` for restart, Escape for cancel-edit then completion dismissal then full-screen exit, and `Alt+Enter` for full-screen mode. Enter and Return continue to start a timer from the expression editor. Full-screen state is temporary and restores the prior normal or maximized state.

Accessibility characterization now covers the primary timer fields and command buttons, About and confirmation dialogs, custom-theme edit/delete controls, and context-menu toggle state. The timer surface declares explicit automation names and help text where visual labels are sparse, while persistent menu options expose labels and checked state through Avalonia menu toggle metadata.

Runtime Avalonia UI text is resource-backed through the Linux application shell to prepare for future localization. Packaging metadata, command identifiers, setting keys, document names, and diagnostic-only backend tokens remain outside that runtime localization boundary.

The **Prompt on exit** context-menu option is enabled by default and persists across restarts. Closing through the title bar, context menu, or direct window close uses one coordinated path: a running or paused timer receives a native confirmation prompt, cancellation leaves it unchanged, and approval waits for queued settings writes before final cleanup. Stopped and expired timers close without a prompt.

The **Advanced options** submenu now contains reverse progress, elapsed-time display, loop timer, loop sound, close when expired, lock interface, do not keep computer awake, and shut down when expired. These options are persisted through the Linux JSON settings store with backward-compatible defaults.

Progress now defaults to remaining-time semantics: duration timers begin at 100% and count down to 0%. **Reverse progress bar** changes that to elapsed-time semantics, counting from 0% to 100%. **Show time elapsed** changes the displayed timer text to elapsed time and freezes at the completed duration after expiry rather than counting indefinitely.

**Loop timer** restarts repeatable duration timers after each expiry cycle while keeping one notification, sound, and visual completion event per cycle. **Loop sound** uses a stoppable playback handle and stops when the expired timer is dismissed, another timer starts, the timer is stopped or restarted, sound is disabled, or the window is closed. **Close when expired** takes precedence over pop-up-on-expiry and requests a deterministic window close after the completion flash delay. It is mutually exclusive with loop timer and loop sound.

**Lock interface** disables timer-modifying commands, context-menu option changes, and edit-mode entry while a running or paused timer is locked. The lock is visible through a restrained border treatment and is cleared when the timer completes or returns to input mode so a later fresh timer starts unlocked unless the option is explicitly selected again.

**Do not keep computer awake** immediately releases an active session-inhibition lease and prevents new keep-awake inhibition while enabled. Turning it off during a running timer reacquires the existing best-effort `systemd-inhibit` lease.

**Wake from suspend** now has an internal `IWakeAlarmService` path and a disabled-by-default `WakeFromSuspendEnabled` setting. When enabled through settings on a capable unsandboxed system, the coordinator schedules one RTC alarm for the earliest running timer and cancels/replaces it as timer state changes. Unsupported or failed scheduling does not affect countdown, notification, sound, or restore behavior.

**Shut down when expired** is wired through a dedicated platform boundary, but the current Linux implementation intentionally exposes an unsupported no-op service and leaves the option disabled. No shell shutdown command is invoked. A real shutdown backend still needs capability detection, confirmation, cancellation, and desktop/session-specific safety work before it can be enabled.

The **Show progress in taskbar** option is enabled by default and persists across restarts. Timer state is mapped to a small desktop-progress request in the Avalonia layer: running uses normal progress, paused keeps visible progress where Unity LauncherEntry has no distinct paused state, expired sends full urgent progress, and stopped clears progress. The Linux services layer selects a Unity LauncherEntry backend only for deliberately recognized compatible desktops/docks or an explicit `HOURGLASS_DESKTOP_PROGRESS_BACKEND=unity` override; unknown environments, Fedora GNOME stock, disabled progress, and failed D-Bus initialization use the unsupported no-op backend. `IDesktopProgressService.IsSupported` means a backend was selected and initialized, not that a dock visibly rendered the one-way D-Bus signal. Exact tested combinations are documented in `docs/linux-port/desktop-progress-compatibility.md`.

The **Show in notification area** option is disabled by default and appears only as an effective setting when Hourglass detects a status-icon-capable desktop session or `HOURGLASS_STATUS_ICON_BACKEND=avalonia` is set and a session bus is available. Unsupported desktops keep the setting masked off and use a no-op backend, so the app remains fully usable without a tray. When enabled, the status icon can show/restore the window, pause/resume, stop, restart, and exit. Hiding the only timer window remains disabled for the current Avalonia backend because backend initialization does not prove the icon is visibly recoverable; this can be enabled later for backends or launch paths that provide a verified recovery path. Title-bar close still follows the normal close path. Exact tested combinations are documented in `docs/linux-port/status-icon-compatibility.md`.

The **Recent inputs** submenu exposes persisted timer expressions without pairing them to title history. Selecting a recent expression enters input mode and does not start a timer automatically; clearing the list updates `app.json` immediately. **Saved timers** are stored separately from global preferences in a versioned document. A saved timer captures the expression, title, and supported timer-behavior options, can be opened into the current single window without auto-starting, and can be removed or cleared. **Open all saved timers** remains disabled until Milestone 6 adds multi-window support.

Active-session restoration is enabled by default. Hourglass persists active timer sessions separately from saved timer definitions, restores running timers from their wall-clock target, restores paused timers with their remaining duration, and restores timers that expired while the app was closed as completed with one startup completion notification/effect. The startup preference can be disabled from Advanced options. Multiple timer windows are coordinated by the Avalonia application shell, and **Open all saved timers** now creates independent windows.

Secondary launches now hand off to the running process through a per-user Unix domain socket. Launching `hourglass` with no arguments requests show/restore/activation for the most relevant existing timer window. Launching with a valid timer expression, optionally preceded by `--title` or `-t`, opens and starts a new independent timer window in the existing process. Malformed local command lines return a non-zero exit code before handoff.

Custom themes are stored in a separate versioned `custom-themes.json` document. A theme contains data-only color values for the timer surface and related visual states; imports reject invalid color data and never load XAML, resources, or code. Saved timers and active sessions can reference a custom theme by stable ID, and missing custom themes fall back to the system theme.

Window title modes are persisted in Linux settings and saved timer options. The supported modes cover application name, time left, time elapsed, timer title, and the implemented combined time/title orderings; title-bar-hidden behavior remains deferred because it is desktop-dependent.

Active-session window geometry is persisted per timer window. Hourglass stores normal bounds plus maximized state, ignores minimized and full-screen states as startup restore targets, validates restored geometry against current monitor work areas, cascades new windows, and debounces geometry writes during resize/move operations.
